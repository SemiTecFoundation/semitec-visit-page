# Editing the two-view page (2D Read · 3D Travel)

> Adapted from `../VisitPageSignal/EDITING.md`. Sections 2–4 and 6–7 apply unchanged to the content and to the 3D view. The **2D view** uses the same content, so a change in `content.js` updates both views.

This project is plain HTML, CSS and JavaScript. It works when `index.html` is opened directly, including offline. Keep the classic deferred script order: **content.js → js/journey.js → js/scene.js → js/core.js → js/chiplayout.js → js/chipmap.js → js/mode-read.js → js/mode-signal.js**. No framework or build process is required.

## 1. Where to make a change

| Change | File |
| --- | --- |
| Foundation name, labels, titles, introductory text, lists | `content.js` |
| Add/reorder a main section or a nested submenu | `content.js` |
| Replace illustrations with actual photos | Add files to `assets/`; update `content.js` |
| Header, bottom bar, mode switch, dialogs, theme colours of both views, the switch transition | `css/base.css` |
| 2D page layout, chip map look, scroll reveals | `css/read.css` |
| 3D view typography, panel, image boards | `css/signal.css` |
| Chip material palette (both views) | The `--chip-*` variables at the top of `css/base.css` |
| Section fade duration (3D) | `--panel-fade` in `css/base.css`, in milliseconds |
| Travel distance, camera height, smoothing, loop size | `JOURNEY_SETTINGS` at the top of `js/journey.js` |
| 2D chip map floorplan: columns, gaps, which section is the power unit | `CHIP_LAYOUT` at the end of `content.js` (positions and the route are generated by `js/chiplayout.js`) |
| Which side a loop turns at each depth | `loopSide()` in `js/journey.js` |
| Partners & supporters (bond pads in 2D and the 3D finale, the I/O side and the columns in the ending) | `SITE_CONTENT.partners` in `content.js`; optional `logo` (an image path, e.g. `assets/logos/name.png`) |
| Events (dated; upcoming on the path, past into the gallery) | `SITE_CONTENT.events` in `content.js` |
| Memory banks and their items (projects, reports, …) | `SITE_CONTENT.memoryBanks` and `SITE_CONTENT.memory` in `content.js` |
| The 2D ending: ecosystem modules (universities, industry, …) | `SITE_CONTENT.ecosystem` in `content.js` (up to 8; layout and traces in `js/ecosystem.js`) |
| Sounds (volumes, tones) | `js/sound.js` |
| Contact details | `SITE_CONTENT.contact.rows` in `content.js` (set `href` to make a row a link, e.g. `mailto:`) |
| The 3D finale geometry (seal ring, pads, wire bonds) | `buildFinale()` in `js/scene.js` |
| Map zoom limits, follow zoom, dive depth, top/3D tilt | constants at the top of `js/chipmap.js` |
| Physical chip models or their arrangement | `js/scene.js` |
| Behavior of the 3D buttons, dialogs, projected images | `js/mode-signal.js` |
| Behavior of the 2D page (cards, reveals, map follow) | `js/mode-read.js` |
| Switching between views, language, bottom bar | `js/core.js` |
| Browser title, description, favicon, no-script message | `index.html` |

Most content and visual changes need only **content.js and the css files**. The renderer reads chip colors at page load, so reload after changing them. Use six-digit hex values for the `--chip-*` colors. Decorative detail colors remain in `scene.js`.

## 2. Bilingual content

Every translated string is a two-item array: **[English, Armenian]**. `SITE_CONTENT` contains four groups:

```js
const SITE_CONTENT = {
  brand: { name: 'SemiTec', subtitle: ['FOUNDATION', 'ՀԻՄՆԱԴՐԱՄ'], tagline: ['…', '…'] },
  sections: [ /* main sections and their children */ ],
  media: { /* named images */ },
  ui: { /* buttons, hints, dialog labels and other shared text */ }
};
```

Keep both translations when editing. Text is inserted using `textContent`, not HTML. Do not add HTML markup inside these strings. The overview title may contain `\n` for its two-line treatment.

## 3. Main sections and submenus

`SITE_CONTENT.sections` is the main route in order. Keep `overview` first and keep at least two main sections. Main sections need these fields:

```js
{
  id: 'events',                        // Stable URL segment
  label: ['Events', 'Միջոցառումներ'],   // Short main-menu label
  title: ['Our events', 'Մեր միջոցառումները'],
  intro: ['Our events go here.', 'Մեր միջոցառումները՝ այստեղ։'],
  items: [['Event information', 'Միջոցառման մասին']],
  media: 'gathering',                  // Key from SITE_CONTENT.media
  children: [ /* submenu nodes */ ]
}
```

Adding or reordering a section automatically updates the main menu, section numbers, map, world length and image placement. IDs must use lowercase letters, numbers and hyphens, begin with a letter, and be unique among siblings. Keep IDs stable once people share links.

A submenu node uses the same fields, except it does not need `label`. Put it in its parent's `children` array:

```js
{
  id: 'workshop',
  title: ['Workshop example', 'Աշխատարանի օրինակ'],
  intro: ['Event introduction goes here.', 'Միջոցառման ներածությունը՝ այստեղ։'],
  items: [
    ['Date and venue', 'Ամսաթիվ և վայր'],
    ['Agenda and speakers', 'Օրակարգ և խոսնակներ']
  ],
  media: 'gathering',
  children: []
}
```

Place this inside Events → Upcoming events to get `#events/upcoming/workshop`. Further nesting uses another `children` array. No hand-written route coordinates or HTML menu links are needed.

Main sections show their submenu choices immediately. Inside a submenu, the reading panel first shows its `intro` and `items`, with an image along the early part of the loop. After travelling 24% of the loop, the panel crossfades to the next choices and small entrances appear ahead on the left. Nodes without children keep showing their items. Provide introductory items for collection nodes too, so every level has content before its next branches.

To change the reveal point for one submenu, add `branchAfter: 0.30` to that node in `content.js`: its choices appear after 30% of its loop. This is a fraction of travelled distance, not elapsed time. Allowed values are 0–0.75; 0 makes choices immediate. Omit it to use `JOURNEY_SETTINGS.nestedBranchReveal` (currently 0.24). The full section map remains an explicit shortcut to any destination.

Keep titles, introductions and lists short for the fixed reading panel; verify both languages at a narrow phone width after editing. Adding many paragraphs requires another content layout, rather than expanding this compact card indefinitely.

The full hierarchy is also available in “Explore sections”. The first `overview` node is an introduction and should not have children.

## 4. Images and captions

Add a file to `assets/`, then register a media entry:

```js
media: {
  workshopPhoto: {
    src: 'assets/workshop-photo.jpg',
    alt: ['Participants at a workshop', 'Աշխատարանի մասնակիցները'],
    title: ['Workshop', 'Աշխատարան'],
    caption: ['Photo caption goes here.', 'Լուսանկարի նկարագրությունը՝ այստեղ։']
  }
}
```

Set a section's or submenu's `media` to `'workshopPhoto'`. Use a local relative path, preserve capitalization, and supply meaningful alt text. Landscape images around 1600 × 1000 pixels work well; previews crop to a 1.6 aspect ratio, while the enlarged dialog shows the whole image. Compress large photos before adding them.

The current assets (`wafer.svg`, `learning.svg`, `gathering.svg`) are illustrative placeholders. Replace captions as well as image paths when adding real photographs.

The controller places one image panel ahead of each main section and two along each optional loop. The first loop image is near its beginning, before the next branching choices; the second is farther around the loop. Only images belonging to the active main/loop context appear. They fade with distance, use depth ordering and have a separate phone position. To change their number or placement, edit `addMainMedia()` and `addVisitMedia()` in `js/mode-signal.js`. Frames, typography and dimensions are in the `.media-board` rules in `css/signal.css`. In the 2D view each main section shows its `media` image once, under its introduction (`.sec-media` in `css/read.css`).

## 5. Appearance

The top of `css/base.css` has the theme variables, once for each view (`[data-mode="2d"]` and `[data-mode="3d"]`). `--font` is the font stack; `--accent` is the UI gold; `--text`, `--muted` and `--background` control the interface. `--panel-width` controls desktop text width. `--panel-fade: 380ms` sets the section fade and reading-panel height transition; the controller reads this value for outgoing-card cleanup.

The chip uses `--chip-board`, `--chip-body`, `--chip-metal`, `--chip-signal`, `--chip-trace` and `--chip-fog`. Signal and UI accent colors are separate controls. Typography is upright sans-serif, with no italic styling.

Responsive rules are in the same file. At 760px and below, text sits below the chip view. Armenian headings have separate size rules for longer labels. Keep focus outlines, current-section underlines and reduced-motion rules when restyling.

## 6. Motion parameters

Distances are world units unless otherwise specified:

| `JOURNEY_SETTINGS` | Meaning |
| --- | --- |
| `sectionSpacing: 44` | Distance between main section anchors |
| `initialZ: 52` | Main route starting coordinate |
| `pixelsPerUnit: 18` | Scroll distance per world unit; larger means a longer/slower journey |
| `smoothingSeconds: 0.13` | Easing time constant; higher values follow scrolling more softly |
| `loopWidth: 55`, `loopDepth: 23` | Shape of an optional closed loop |
| `nestedLoopScale: 0.72` | Each additional nesting level multiplies loop size by this amount |
| `cameraHeight: 3.15` | Eye height above the chip |
| `fieldOfView: 62` | Desktop field of view in degrees; phones use 68 in `js/scene.js` |
| `lookAhead: 18` | Distance used to aim along the tangent |
| `branchSignAhead: 20` | How far ahead the small branch entrance is placed |
| `branchSignLeft: 2.8` | Lateral offset to the left of the trace on desktop |
| `nestedBranchReveal: 0.24` | Fraction of a submenu loop travelled before its child choices appear; overridden by a node's `branchAfter` |
| `scrollIdleMs: 240` | Minimum quiet time before unused scroll space can be reclaimed; camera easing must also have settled |
| `maxPixelRatio: 1.5` | Rendering resolution cap |

Tune one parameter at a time, run the validator, and visually inspect a nested loop. Very small loops create tight turns and can make scenery overlap. The current scale is designed for the supplied three-level content tree.

## 7. Navigation contract — preserve when editing with an LLM

1. The main route stays continuous and gently curved. Section changes update text without moving the camera to a preset section pose.
2. Small entrance signs appear on the left edge of the chip trace, connected by a short visual wire. Their links come from the current node’s children. Reading-panel links provide equivalent keyboard/fallback access. Main-section choices are immediate; submenu choices wait until `branchRevealAt()` so introductory text and images come first. Ignoring an entrance must never add a branch to the scroll itinerary.
3. Selecting a direct child inserts a loop at the **currently displayed** camera position. It does not teleport to another location.
4. Every loop starts and ends at the same point with the same tangent. Scrolling past its end resumes the parent and removes the completed loop from the scroll itinerary. A nested loop resumes its parent loop first. Backing out or leaving through navigation removes inactive branches too. A completed branch can only be entered again through an explicit navigation action, never merely by scrolling backward and forward.
5. The itinerary stores curve segments. Inserting a loop splits the current segment into “before / loop / after” and temporarily adds its length to the scroll track. Preserve the remaining parent segment, including a zero-length tail at the final endpoint. `pruneInactive()` removes inactive visits, merges adjacent parent segments, and returns a coordinate remapping. Apply it to the logical camera distance, scroll target and pending navigation target. Preserve native scroll position through `ScrollSpace.holdPosition()`; **do not call `scrollTo()` during branch cleanup**. The browser must retain its current forward motion and momentum. `settleScrollSpace()` resets the offset and reclaims unused track only after both native motion and camera easing stop. World position and viewing direction stay unchanged during both operations. All native/logical coordinate conversions must go through `ScrollSpace`.
6. Main-menu shortcuts select the resumed main segment at a shared junction. Parent-submenu shortcuts select that parent's segment, not an already inserted nested child.
7. Curves use **arc length** for consistent travel speed. One frame loop eases scroll distance; the camera follows the path tangent.
8. WebGL world geometry and the canonical loop mesh are built once. Loop instances reuse that mesh with a transform. Do not rebuild the chip when text changes. Completed loop geometry fades out for 500ms after its logical removal; image panels and entrance labels are also cleaned up. Only particle positions are dynamically uploaded each frame.
9. Keep native wheel/touch scrolling, keyboard navigation, URL hashes, back/forward behavior, dialogs and Still view. Do not add scroll snapping or intercept wheel events to advance a whole section.
10. Section cards crossfade, with only the incoming card interactive. Their container height transitions on mobile so different content lengths do not cause a jump.

Browser scrolling rounds to pixels. Keep the scroll-track height rounded upward and return shortcuts a couple of CSS pixels past the loop seam; otherwise a button can stop at 99.99% on the child side of a junction.

Only the currently explored branch and its ancestors remain in the itinerary. A pending explicit map/deep-link navigation may retain its target branches until arrival; cancelling that navigation removes unentered branches. Reloading a deep link reconstructs a fresh route at its canonical section anchor. This is scroll history, separate from ordinary browser Back/Forward navigation. The prototype uses no cookies or local storage.

Entrance appearance is controlled by `.branch-sign`, `.branch-wire` and `.branch-entrances` in `css/signal.css`. Text comes from `content.js` (`ui.branchTitle`, `ui.branchEnter`, and child titles). Placement uses `JOURNEY_SETTINGS` plus `renderBranchEntrances()` / `updateBranchEntrances()` in `js/mode-signal.js`; no duplicated list of destinations is maintained.

`js/journey.js` is independent of the DOM and WebGL, so geometry can be tested without a browser. `js/scene.js` receives the current pose and samples of the composed path. `js/mode-signal.js` connects native scrolling, content and the renderer while the 3D view is showing; `js/core.js` hands control between the views.

## 8. Verification

Run from this folder:

```sh
node validate.cjs
python3 -m http.server 8768 --bind 127.0.0.1
```

Open `http://127.0.0.1:8768/`. The validator checks translations, IDs, image paths, route resolution, arc-length speed, loop/nested-loop closure, forward-facing joins, main-menu junction selection, temporary branch cleanup, native scroll mapping during removal and idle compaction, delayed nested entrances and loops at the final endpoint. It does not replace visual browser testing.

Manually verify:

- Scroll past Events without choosing a submenu: Impact follows smoothly.
- Enter Initiatives → SemiTec Academy: introductory items and an image appear first, without Programs or Learning resources links. Scroll about a quarter of the loop: these choices fade in. Enter Programs and complete its loop; Academy resumes with its choices still available.
- Choose Upcoming events, then Workshop. Scroll to the end: Upcoming events resumes. Keep scrolling: Events resumes at the original junction, followed by Impact.
- Continue scrolling across a loop exit: native scrolling must keep moving forward while the camera joins the parent path, without a rewind. Once motion settles, the scroll track returns to its original main-only length. Then scroll backward and forward across the junction: the completed submenu must not reappear. Click an entrance to re-enter deliberately.
- Use main-menu links and breadcrumbs, and open a deep URL such as `#events/upcoming/workshop`.
- Open an image and close it with Escape. Open the section map and follow a nested link.
- Switch EN / ՀԱՅ, test a phone width and Still view, and inspect the browser console.

If the preview browser retains old assets, increment the `?v=` numbers in `index.html` and reload. Stop the preview server with Ctrl+C after testing.
